# Implementation Plan: Admin UI Refresh Dashboard

**Branch**: `002-admin-ui-refresh` | **Date**: 2025-11-16 | **Spec**: `specs/002-admin-ui-refresh/spec.md`
**Input**: Feature specification from `specs/002-admin-ui-refresh/spec.md`

## Summary

Refresh the CMS admin experience by replacing the current `/admin` placeholder with a dashboard-style layout that surfaces key content metrics, a 14‑day published‑articles chart, upcoming items, and recent activity. The dashboard will use the existing YEWAPDC colour scheme, shadcn/ui components for layout and cards, and Heroicons (or similarly styled coloured icons) for navigation and metric visuals.

**Language/Version**: TypeScript, React 19, Next.js 16 (App Router)  
**Primary Dependencies**: Tailwind CSS v4, shadcn/ui (cards, layout primitives, buttons, nav), @heroicons/react (outline/solid icons), existing YEWAPDC component library  
**Storage**: PostgreSQL via Drizzle ORM (existing `articles`, `events`, `promotions`, `media` tables)  
**Testing**: Jest for integration/unit tests; Playwright for E2E admin flows  
**Target Platform**: Web app deployed on Node/Next.js hosting (e.g., Vercel)  
**Project Type**: Web application (single Next.js repo with admin + public UI)  
**Performance Goals**: Reuse existing budgets (admin pages should load key dashboard metrics within ~3s on typical dev hardware/network)  
**Constraints**: Preserve current colour palette; avoid heavy charting dependencies (prefer CSS/SVG-based micro‑chart); maintain WCAG 2.1 AA accessibility; respect RBAC and existing auth  
**Scale/Scope**: Small admin audience (internal staff); dashboard is a single high‑value screen plus shared layout/nav used across `app/admin/*`

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Security**: No new external APIs or auth flows; dashboard consumes existing services (`article-service`, `event-service`, etc.) inside server components. RBAC continues to be enforced via existing admin layout guards. → **PASS**
- **Code Quality**: Plan reuses the existing Next.js + TypeScript structure; new components will be small, typed, and follow current linting rules. → **PASS**
- **Data Integrity**: All metrics are derived via Drizzle from existing tables; no schema changes required. → **PASS**
- **Performance & Accessibility**: Dashboard will use server components and simple aggregated queries; UI reuses Tailwind/shadcn primitives and honours skip links and ARIA labels. → **PASS**
- **Testing Discipline**: At least one Playwright update will assert dashboard visibility and navigation; integration tests may be added for metric helpers as needed. → **PASS**
